# 实验 v2：公平对局与泛化规则

## 已启用的实验

模型仍为 Jev。OpenAI Decisions 只预留内部模型标识、结果校验和数据维度，不开放玩家选择、不分配流量、不把普通 GPT-6 Luna 当作 Decisions。正式 API 发布后还需完成真实协议适配和集成验证，不能仅修改模型名就启用。

| 游戏 | 泛化规则 | 合理性与验证 |
|---|---|---|
| 石头剪刀布 | 石头胜布、布胜剪刀、剪刀胜石头 | 保持循环克制与均匀混合均衡；模型直接选动作，另答预测题 |
| 囚徒困境 | 协作（猎鹿）博弈：CC=4/4，CD=0/3，DC=3/0，DD=2/2 | 不再称为囚徒困境的收益结构；CC、DD 都是纯策略均衡，对手合作概率高于 2/3 时合作更优 |
| 最后通牒 | 拒绝后提议者得1、回应者得2，接受仍分10 | 回应者接受大于2的提议优于拒绝；角色逐轮轮换 |
| 布洛托上校 | 10兵分4地：平原1分；隘口2分（有效兵力最多3）；要塞3分（领先至少2兵才胜）；港口4分（每2兵折算1战力） | 同一地平局双方0分，比较所得地域分。玩家有286种分配；模型排除历史估算最低的31种，使用255种。枚举81,796对组合，计分对称，每种分配都能被反制 |
| 吹牛骰子 | 1不再万能，允许叫1到6 | 同样逐步加价与质疑，隐藏骰仍独立均匀；所有合法叫点均可选 |
| 德州扑克 | 摊牌必须恰好1张底牌+4张公共牌 | 牌型排序、下注机制不变；双方约束相同。成牌、摊牌和提示模式胜率都采用此规则 |

所有同时行动游戏只提交已结束回合；骰子、扑克只提交模型自己的私有信息和公共记录。严格请求 schema 拒绝额外字段。对局状态当前仍由浏览器维护，本次防止模型偷看，不提供防恶意客户端篡改的服务器权威对局。

Raw/Hinted 共享规则、历史、合法动作与动作顺序。Hinted 只额外提供分析。布洛托恢复自由分兵：常规人机均66种；泛化人类286种、模型255种，排除历史估算最低31种。两种模式使用相同候选，不读取本轮玩家选择；骰子不再根据私有骰筛选选项。扑克双方沿用原本下注机制，两个模型模式共享同一离散下注集合。

## 分配与统计

每个游戏、每个访问会话获得固定条件，最长缓存2小时；跨游戏独立分配。同一会话重开对局保留条件，避免为了获得特定条件而重复刷新。手动切换会重新开始对局并标记 `manual`。

常规与泛化共用同一个游戏页面，通过按钮切换。每次规则切换都先显示两种规则的对比弹窗，标明目标版本；取消不改变当前对局。每个游戏首次进入自动分配的泛化版时，先显示同样的说明，关闭后才初始化对局和模型请求。页面持续显示泛化规则，弹窗复用原有颜色、圆角和按钮样式，采用原有单栏确认框布局。

`ExperimentAllocator` Durable Object 串行处理分配，根据当前游戏已完成的纯模型、自适应分配对局，动态向不足组倾斜；尚未完成的活跃分配暂计0.5局，避免并发访问全部挤入同一组。已完成的分配不重复计预留权重。2小时后清理过期预留。

当前4个单元目标占比：直觉/常规56.25%、直觉/泛化18.75%、提示/常规18.75%、提示/泛化6.25%。未来正式开放两模型时各减半，形成8个单元，模型比1:1。采用缺额权重并保留5%目标分布随机探索；这是随机纠偏，不保证任意时刻比例精确。出招策略沿用独立75%取最高、25%按概率，不混合比较。

数据库只采纳同意共享的数据。不共享、未完成对局不能用于纠偏。API失败导致练习机器人接管的混合局和纯练习局不纳入模型对局比较。手动、离线随机分配独立统计。`experiment_matches` 每局一条，`log_batches` 防重试重复写入，`agg_v2` 与旧 `agg` 分离；历史事件保留为实验1。

数据洞察使用原版单一页面。默认“全部版本”：普通规则合并旧agg与新agg_v2，泛化仅采用新规则记录。“当前版本”按正在运行的游戏元数据版本及经核对的玩法兼容清单筛选，不把历史版本重标为当前版本。出招策略仍分别筛选；分配来源不再作为公开筛选，三个来源均可展示，但内部动态均衡算法仍只采纳合格的自适应对局。移除新实验/历史入口及公开分配比例图。保留原版六游戏图表、概率校准、统计卡片及图表/表格切换。跨版本汇总用于描述整体情况，不是严格的模型对照；原始版本和实验字段保留。


## OpenAI Decisions 接入预留

- 请求已有 `opponent`、`variant`、`experiment`；前端继续请求自己的 Worker `/decide`。
- `worker/src/models.js` 提供模型状态、可用性和归一化结果校验；`luna` 默认关闭。
- `shared/prompts.js` 将可见状态和问题列表构建为统一决策契约；当前 `buildJevRequest` 的 `model` 字段仅用于 Jev。
- API正式上线后，在 `worker/src/decision-provider.js` 补全 OpenAI adapter，将统一 `state/questions` 映射到正式请求，并将返回值映射为 `answers`。离散动作必须包含完整选项概率，概率题在[0,1]；不能用模型自行写出的“置信度”冒充原生分布。
- Cloudflare 优先使用届时验证过的原生接口；否则使用 AI Gateway provider-specific/custom provider 路由。端点、模型ID与认证全部在服务端配置，不从浏览器接受任意上游URL或密钥。
- 实测鉴权、合法选项、超时、概率语义、数据标签及规则隔离后，才把模型加入 `availableModels`。数据页自动按可用模型展开；底层统计与分配维度均已支持两模型。
- 不进行自动上线或定时探测；正式发布不代表本账号自动获得权限。

## 发布顺序

1. 用 Node 22.13+ 运行 `npm ci`、`npm test`、`npm run test:dom`（包含SQLite迁移、日志幂等和模拟接口的四组DOM联调）。
2. 在测试环境完成真实 Jev/Cloudflare 调用。布洛托66/255选项请求必须验证上游兼容性与响应延迟；本地mock测试不能替代这一步。
3. 在 `worker/` 执行 `npx wrangler d1 migrations apply jev-lab-data --remote`，备份后应用增量迁移0005，勿删除历史表。
4. `npx wrangler deploy` 发布含 `EXPERIMENTS` Durable Object 绑定及v2迁移的Worker。
5. 再发布静态前端 v2.0.0，通知已打开网页的玩家刷新。

没有数据库或分配服务暂不可用时，前端退回独立随机3:1分配并标记 `offline`，不会声称动态纠偏已生效。只部署前端不部署后端，会导致新规则请求失败并退回练习模式。

## 布洛托候选上限

常规：10兵、3地域，人机均66种分配。泛化：10兵、4地域，玩家自由选择286种；模型保留历史估算最高的255种，排除31种。估算为胜率加半数平局概率（P(win)+0.5P(draw)），不是Jev返回的概率。没有历史时使用固定先验；此后只用此前对手分兵，双方本轮出招保持隐藏。候选计算在前端和Worker使用同一函数，Worker校验提示模式候选，不信任客户端自行更换。候选最终按中性枚举顺序发送，直觉/提示相同。

动作空间在人机之间存在差异，应在研究结论中明确，不能称为完全对称动作空间实验。玩家保留原来的加减兵力、均衡/随机/重复方案及出兵流程。泛化地形为平原、隘口、要塞、港口；新地形SVG复用原有线条、阴影和地图色彩。

Windows验证与上线步骤见 [WINDOWS-RELEASE.md](WINDOWS-RELEASE.md)。

## 2.0.2：玩法兼容与同页对比

核对基线：`3cd842f42f10991af77bad9af174cb508b2435c5`。当前玩法视图可纳入旧1.4的常规PD（两模式）、最后通牒（两模式）、布洛托（仅直觉）。前两者收益、动作、轮次和可见信息保持一致；布洛托直觉仍是全部66个分配。提示文字存在改动，因此标记为“玩法兼容”，不声称完整实验条件一致。其他旧版本未核对、猜拳出招机制变更、布洛托提示候选变更、骰子/扑克尚未完成兼容审计，均仅保留在全部版本中。清单精确匹配目标版本，未来升版不会自动继承兼容关系。

对比是原页面中的第三个规则按钮，使用相同统计卡片和图表/表格切换。仅选择当前游戏版本的新实验、动态分配、完整且非混合的Jev对局；实际模型版本分别显示，不合并。直觉和提示、greedy/sample分别筛选。常规和泛化各显示局数、去重匿名浏览器编号数、未知编号局数、双方胜率、平局率及有收益记录的平均收益和分母。不将旧记录伪装为新实验对照，不将缺失值填成零，不把模型版本不一致的两组直接作差。

玩家计数由Worker使用events/experiment_matches汇总，仅向页面返回计数；不返回编号。首次end记录锁定版本/玩家元数据，model事件验证仅存在一个实际模型，避免重发end放大局数。重复玩家可参与多局甚至两组，两个组的玩家数不能直接相加，页面不提供未经聚类处理的显著性/置信区间；胜率差仅为描述性百分点差。没有同组对应数据时不显示差值。收益不跨规则直接作差。接口失败率/延迟没有可靠历史采集字段，本版不虚构这些指标。

发布需要更新Worker及前端，无新增数据库迁移。统计响应新增comparisons，缓存键升级；前端用发布版本更新请求URL，避免旧响应被误当作新接口。新Worker与旧前端兼容。

## 2.0.3：练习历史与手机筛选

全部版本保留所有常规练习历史，不受Jev的greedy/sample筛选影响。兼容审计进一步确认旧1.4常规PD和最后通牒的练习机器人算法未变，因此practice模式也纳入当前玩法。其他旧练习算法未经核实或候选发生变化，仅放在全部版本。概览明确提示练习局数、机器人动作数，严格模型对比仍排除练习和混合局。

手机筛选组使用等宽网格、最小44px触控高度、允许文字换行。对比时版本显示为固定说明而非禁用按钮，退出后恢复此前版本选择。DOM测试验证模式切换与版本状态，尚未完成真机视觉验收。本次仅前端变化；若已部署2.0.2统计Worker，无需再次部署Worker或迁移数据库。
